T-MATS: Compressor HX Library Block

Purpose

This block can be used to simulate the performance of a compressor using basic thermodynamic equations, properties, and table-lookups. This block is a modified version of the standard T-MATS Compressor library block that adds-in features for modeling the non-adiabatic effects heat soak and tip clearances. Heat soak refers to the bulk heat transfer between the gaspath and surrounding structure of the compressor. Tip clearance refers to the gap between the blade tips and outer containment structure/seal, which is impacted by thermal expansion of the compressor parts. The tip clearance model approximates the impacts by modeling the compressor as a single stage. Both heat soak and tip clearances have impact on compressor performance and operabilty which are accounted for through performance map adjustments


Background

This block models a compressor with the effects of heat soak and tip clearances. It leverages a modified version of the standard T-MATS Compressor library block to compute the outputs of the compressor under adiabatic conditions without tip clearance variations impacts. The modifications to the standard T-MATS compressor block enable the compressor performance map scalers and the location of the stall line to be adjusted based on computed performance impacts relative to heat soak and tip clearance effects. The block utilizes the Compressor_SLmod_TMATS.c script to compute the adiabatic output gas characteristics and other variables.

The adiabatic outputs are modified through a heat soak model that updates the output enthalpy and temperature based on the computed heat transfer with the surrounding engine structure and any additional heat transfer that is prescribed. In addition, the current engine operating conditions and thermal state is utilized to approximate the tip clearance. Outputs of the heat soak model and tip clearance model are used to predict performance impacts that are applied through modificaiton of the compressor map scalers. These scalers feed back into the standard T-MATS Compressor library block creating an implicit mathematical problem. Thus, the T-MATS Newton-Raphson solver block is used to iterate the solution until the output temperature of the compressor converges.

Adiabatic Compressor Performance Model

To compute the input enthalpy and entropy, Compressor_SLmod_TMATS.c uses a table-lookup method using the input temperature, pressure, and fuel to air ratio as reference values.

A couple of values related to the fluid flow are then calculated using the following equations: $$\delta = \frac{Pt_{In}}{\textit{C_PSTD}}$$ $$\Theta = \frac{Tt_{In}}{\textit{C_TSTD}}$$ In the equations above, C_PSTD and C_TSTD are standard day conditions for pressure and temperature, respectively. Using the calculated values from these equations, the corrected flow can be determined by the following: $$Wc_{In} = W_{In}*\frac{\sqrt{\Theta}}{\delta}$$ Likewise, the corrected shaft speed is determined by: $$Nc = \frac{Nmech}{\sqrt{\Theta}}$$

General compressor performance is dictated by a compressor map that relates corrected shaft speed and an arbitrarily defined monotonically increasing Rline to corrected mass flow, pressure ratio, and efficiency. Values in this map may be scaled (for example 100% shaft speed might correlate to 20,000 rpm), so in this discussion all values taken from the map will be refered to as Map parameters.
The compressor speed map is determined by using the corrected shaft speed and the user-specified corrected speed scalar constant (C_Nc), as seen in the following equation: $$ NcMap = \frac{Nc}{\textit{C_Nc}} $$ The value of C_Nc is dependant upon which iDesign (iDes) option is used.

The iDes option can be accessed by double clicking the block, navigating to the iDesign tab, and entering 0, 1, or 2 for the option of iDesign_M.

  • If 0 is input, iDes will be enabled and the compressor map scalars (such as C_Nc) will be based on design variables specified by the user in the iDesign tab. These values are output to a specified file (FVar_M).
  • If 1 is input, the scalars will be determined from a specified file (FVar_M) that is uploaded by the user and specified in the iDesign tab.
  • If 2 is input, the scalars will be determined by the scalars specified in the C-Map tab (such as s_C_Nc_M); no values from the iDesign tab will be used.
For more information on how to enable iDes and the different options for how to use it, see the Mask Variables table at the bottom of this page.

To compute the total flow input, the script utilizes the user-specified compressor map, interpolates the results, and then scales the results using the user-specified flow scalar constant according to the following equation: $$ WcCalc_{In} = WcMap * \textit{C_Wc}$$ The value of the flow scalar constant C_Wc is dependant upon which iDes option is used, as previously described and as detailed in the Mask Variable table at the bottom of this page.

In order to determine the output total pressure, the pressure ratio that the compressor is operating at must first be determined. The pressure ratio is determined by the following equation: $$ PR = \textit{C_PR} * (PRMap - 1) +1 $$ in which PRMap is determined by interpolating the compressor map and C_PR is dependant upon which iDes option is used. Once the pressure ratio is calculated, the total output pressure can be calculated using the following equation: $$Pt_{Out} = Pt_{In}*PR$$

The overall efficiency of the compressor can be determined by the following equation: $$Eff = EffMap * \textit{C_Eff} $$ in which EffMap is determined by interpolating the compressor map and C_Eff is dependant upon which iDes option is used.

To compute the output total enthalpy, the script assumes that the compressor is isentropic such that input entropy is equal to output entropy. This allows for a table-lookup of the ideal total temperature using the entropy, pressure, and fuel to air ratio. An additional table-lookup is then done to determine the ideal total enthalpy using the ideal total temperature and fuel to air ratio. The final total enthalpy output is then determined using the following: $$ ht_{Out} = \frac{htIdeal_{Out} - ht_{In}}{Eff} + ht_{In} $$ The actual temperature output is then determined via a table-lookup using the actual total enthalpy and fuel to air ratio.

The output flow is determined by the following equation: $$ W_{Out} = W_{In} - Wbleeds $$ In the above equation, Wbleeds is the amount of flow that has left the system and can be determined in two ways. First, Wbleeds can be calculated based on user-specified customer bleeds (constant bleed value) and/or it can be calculated based on user-specified fractional bleeds. Multipule or none of these bleed flows can be specified by enabling or disabling these options.

These two types of bleeds are determined by the following equations. In the code, the customer bleeds are evaluated first and then the fractional bleeds are evaluated and added to the customer bleed in order to determine the total flow that is bled off.

Total bleed flow for the compressor is calculated by summing the specified flows: $$Wbleeds = \sum Wfrac + \sum Wcust$$ In the above equation, Wcust are the values C_CBD_M (mask variable). The Wfrac values are the values C_FBD_M (mask variable) multiplied by input flow, Win.

While computing the bleed, the script also calculates the total enthalpy and pressure that is lost due to each bleed. These values are determined by the following equations, respectively: $$htcust_{Out} = ht_{In} + FracBldht*(ht_{Out} - ht_{In})$$ $$Ptcust_{Out} = Pt_{In} + FracBldPt*(Pt_{Out} -Pt_{In})$$ In the above equations, FracBldht and FracBldPt refer to the fractional enthalpy and pressure gains by the flow before the bleed occurs. Although imperfect, these factional values are meant to simulate bleed at an internal stage. So, for example, if bleed occurs at stage 4 of an 8 stage compressor these fractional values might be 0.5. In addition to calculating the total enthalpy and total pressure for the bleed, the total temperature is determined by a table-lookup method using the total enthalpy as the search criteria.

The output power is determined in a similar manner as the output flow. Like the output flow, the output power depends on both the input power and the amount of power bled off; the equation used to solve for the output power is below. $$Pwr_{Out} = Pwrb4bleed - PwrBld$$ The ideal power stored in the system (Pwrb4bleed) is given by: $$ Pwrb4bleed = W_{In}*(ht_{in} - ht_{out})*\textit{C_BTU_PER_SECtoHP}$$ in which C_BTU_PER_SECtoHP is the constant to convert BTU/s to HP.

The power that bleeds from the system (PwrBld) is determined by sumation of the power that is bled off. $$PwrBld = \sum Wbld*(htbld_{Out}-ht_{Out})*\textit{C_BTU_PER_SECtoHP}$$ where bld variables are fractional and/or customer bleed values.

The output torque to the shaft is determined by the output power and the shaft speed, as seen in the following equation: $$Torque_{Out} = \textit{C_HP_PER_RPMtoFT_LBF} * \frac{Pwr_{Out}}{Nmech}$$ in which C_HP_PER_RPMtoFT_LBF is a constant used to convert the units.

The computation of the normalized flow error depends on if iDes is enabled or not. If iDes is enabled, NErrorOut is determined by the following: $$NErrorOut = \frac{(Rline - RlineDes)}{Rline}$$ In the above equation, the Rline values are determined from the user-specified compressor map. If iDes is disabled, NErrorOut is determined by: $$NErrorOut = \frac{(Wc_{In} - WcCalc_{In})}{Wc_{In}}$$ Note: Divide by zero protection is implmented on these equations and if Rline is equal to zero, NErrorOut will be equal to 100. This will also occur if WcIn is equal to zero.

To determine the available stall margin, the following equation was used: $$SMavail = \frac{SPR - PR}{PR} * 100 $$ in which $$SPR = \textit{C_PR}*(SPRMap -1)+1$$ where SPRMap is determined by interpolating values on the compressor map and C_PR is dependant upon which iDes option is used. The stall margin map is then determined using the following: $$SMMap = \frac{SPRMap - PRMap}{PRMap} * 100$$

For information on which output values are contained within the block outputs, see the Compressor Output table shown later in this file.

Heat Soak Model

The heat transfer due to heat soak is calculated by: $$qHS = CH*A*(T_m - Tgp)$$ where qHS is the heat, Tm is the metal/structure temperature of the bulk component, Tgp is the average temperature of the gaspath (Tgb = 0.5*(Tin + Tout) where Tin and Tout are the compressor inlet and exit total temperatures respectively), A is the effective surface area associated with the bulk mass of the compressor structure, and CH is the convective heat transfer coefficient. CH is computed with the equation below: $$CH = CHdes*(W_{in}/Wdes)^{0.8}$$ Win is the mass flow rate entering the compressor and Wdes is the inlet mass flow rate at the design point, which corresponds to the design convective heat transfer coefficiencet CHdes. The bulk temperature of the component structure is dynamic and its rate of change is calcuated with: $$\frac{dT_m}{dt} = \frac{qHS}{Mm*Cpm}$$ where Mm is the mass of the bulk mass used to model the thermal inertia of the compressor, and Cpm is the specific heat at constant pressure for the bulk mass. dTm/dt is integrated outside of this block to get Tm (similar to how shaft acceleration is integrated to get the shaft speed). The block allows for a generic heat injection/removal (qext) to be added to the heat related to heat soak. $$q = qHS + qext$$ The enthalpy is adjusted with $$ht_{out} = ht_{out,ad} - q/W_{in}$$ where htout,ad is the adiabatic output enthalpy. The output temperature, Ttout, is computed with a T-MATS thermodynamic subroutine. Any bleed outputs must also be updated. For each bleed the enthalpy is re-calculated with: $$htBld_{out} = ht_{in} + FracBldht*(ht_{out} - ht_{in})$$ and the shaft power as also updates with: $$Pwr_{Out} = W_{in}*(ht_{in}-ht_{out}) - \sum W_{bld}*(htBld_{out}-ht_{out})$$ The shaft torque is updated utilizing the new shaft power value.

Tip Clearance Model

The tip clearance model attempts to approximate axisymmetric tip clearance variations due to thermal expansion and centrifugal forces. The compressor is partitioned into 3 subcomponents: the blade (of which there are many), the rotor disk (to which the blades are attached), and the casing. A one-dimensional thermal expansion model is applied for each subcomponent. The change in subcomponent radius (for rotor and casing) or length (for the blades) was determined with: $$\Delta r = r_o*(1+\alpha *\Delta T)$$ Note that ro is a reference radius or length, ΔT is the temperatue difference of the component relative to the reference temperature corresponding the the reference radius or length, and α is the linear thermal expansion coefficient.

Since the thermal expansion utilized the temperature of the subcomponents, it is necessary for the model to capture their temperature variation. The blade temperature utilizes a lumped mass model similar to the heat soak model. The rate of change in blade temperature is computed with: $$\frac {dT_b}{dt} = \frac{CHb*Ab}{Cpb*Mb}(Tgp - T_b)$$ where Tb is the blade temperature, Ab is the surface area of the blade, Mb is the mass of the blade, Cpb is the specific heat of the blade, CHb is the coeffiicent of convective heat transfer acting on the blade, and Tgp is the average temperatue of the gaspath, and Tref is $$T_{ref} = Tgp + \varsigma * (Tgb - T_{cool,b})$$ where Tcool,b is the temperature of the cooling air, ς is the film cooling coeffient and has a value between 0 and 1. This is a reminant from a turbine application and it should be noted that compressor blades are not typically (if ever) cooled. Thus, assigning ς = 0 is recommended. The coefficient of heat transfer is determined with an equation of the same form as was presented for the heat soak model. The rate of change in blade temperature should be integrated outside of this block to update the blade temperature each timestep.

The casing temperature must be computed outside of this block. It is suggested that a 1-D thermal conduction T-MATS block be used to compute the radial variation of the temperature though the casing thickness and to compute the average temperature to represent the subcomponent temperature. The inner surface boundary condition is set with the gaspath on the inner surface. The outer surface is likely subjected to undercowl air bled from the bypass.

The rotor has the most thermal mass of the subcomponents and is expected to be well coordinated with the bulk component temperature. To maintain consistency with the bulk temperature of the compressor from the heat soak model, the rate a change in rotor temperature is a scaled version of the bulk component temperature. $$\frac {dT_r}{dt} = \frac {dT_m}{dt} \frac{T_{cool,r}-T_r}{Tgp-T_m}$$ Logic was added to prevent division by zero. It is assumed the rotor is cooled with the compressor exit air and thus Tcool,r is set accordingly.

The strain models are applied after thermal expansion. The equations used in the computations are given below. $$r_r = \rho *\frac{1-\nu}{4*E}*{(\frac{2*\pi}{60}N)}^2*r_{r,u}^2$$ $$L_b = \rho *\frac{1}{E}{(\frac{2*\pi}{60}N)}^2*L_{b,u}^2(r_r+L_{b,u})$$ Note that ρ is the density of the subcomponent, E is Young's Modulus of Elasticity, ν is Poisson's ratio, N is the shaft speed in rpm, rr,u is the unstrainted rotor radius, and Lb,u is the unstrained blade length. The tip clearance, TC, is the gap between the rotating components and the inner radius of the stationary containment structure and is thus computed as $$TC = r_{c} - (r_{r} + L_{b})$$ The performance modifications are based on differences in tip clearance as compared to nominal tip clearance for which the base performance map (scalers) are assumed to be consistent. The user must specify the nominal tip clearance, which should correspond to the nominal performance. The nominal tip clearance is an input to the block and could be prescribed a number of ways. For instance, for a notional engine system where such data is not provided, one can use steady-state data to guide the formulation of a look-up table that covers the range of operation.

Performance Impact Model

The compressor perforamnce and operability is adjusted through scaling of the corrected speed, scaling of the efficiency, and shifing of the stall line. The speed and efficiency map scalers are multiplied by a speed scaler modifier Cc,N and efficiency scaler modifier Cc,η respectively. Below is the expression for the speed scaler modifier $$C_{c,N} = 1 + C_{N,BL}*\frac {Tb-Tgp}{Tgp} - C_{N,\rho}*\frac {qHS}{W*Cp*Tgp}-C_{N,TC}*\frac {\Delta TC}{g}$$ where CN,BL is the coefficient of impact for boundary layer effects, CN,ρ is the coefficient of impact for density effects, CN,TC is the coefficent of impact for tip clearance effects, and g is the staggered blade gap. The expression for the efficiency scaler modifier is conditional based on the varation of the tip clearance relative to the span of the blade, S. It consider both the actual tip clearance to span ratio and the nominal (nom) tip clearnce to span ratio. When both TC/S and (TC/S)nom are both &le 0.036 the following expression is used where ΔTC = TCnom - TC. $$C_{c,\eta} = 1 + 1.6* \frac{\Delta TC}{S}$$ When both TC/S and (TC/S)nom are both > 0.036 the following expression is used. $$C_{c,\eta} = 1 + 0.5* \frac{\Delta TC}{S}$$ Otherwise the following expression is used. $$C_{c,\eta} = 1 + sign(\frac{\Delta TC}{S})*(0.5*(max(\frac{TC}{S},(\frac{TC}{S})_{nom})-0.036) + 1.6*(0.036 - min(\frac{TC}{S},(\frac{TC}{S})_{nom})))$$ The stall pressure ratio is adjusted through the following equation $$SPR = m_{SL}*SPR_{0} + b_{SL}$$ where SPR_{0} is the adiabatic stall pressure ratio and the stall line modifier scaler and bias are computed with: $$m_{SL} = 1 - C_{SPR,q}*\frac{q_{HS}/W}{ht_{in}-ht_{out,A}} + C_{SPR,TC}*\frac{\Delta TC}{g}$$ $$b_{SL} = C_{SPR,q}*\frac{q_{HS}/W}{ht_{in}-ht_{out,A}} - C_{SPR,TC}*\frac{\Delta TC}{g}$$ Note that CSPR,q and CSPR,TC are the coefficients of impact for heat transfer and tip clearance effects respectively and htout,A is the exit enthalpy under adiabatic conditions. The performance and operability modifiers are fed back into compressor calculations that determine adiabatic performance. The loop of calculations executes until convergence of the exit temperature is achieved.

Parameterizing the Model

The updates to incorporate heat soak and tip clearance impacts introduces numerous parameters that must be defined. Among these parameters are material properties, surface areas and component masses sufficient for a lumped mass heat transfer models, "design" flow rates and heat transfer coefficients for convective heat transfer coefficient approximation, initial component/subcomponent temperatures and sizes (length/radius), nominal tip clearances, and impact coefficients for the performance and operablity impact models. Some of the parameters are straight foward. For example, material properties can be defined from data specific to the materials of the components/subcomponents. Other parameters can be prescribed with some engineering judgement and further tuned to achieve realistic behavior. For instance, there could be freedom in choice of the "design point" heat transfer coefficients to tailor the temperature response of the components/subcomponents. For some other parameters, more upfront work may be warranted to set their values. Specifically, initial conditions fall into this category and they should be determined within the setup scripts/functions for the model. The component/subcomponet temperatures should be able to be inferred from gas path initial conditions. The intial rotor, casing, and blade sizes for the tip clearance model can be initialized at a presrcibed condition and given time to reach equilibrium. Alternatively they can be calculated for an equilibrium state at the desired model starting point using MATLAB functions that mimic the calculations for determining the subcomponent deformations. The functions are in the "TMATS/TMATS_Library/MATLAB_Scripts/+TMATS" folder and are listed below:

ThermalExpansion1D.m: performs 1-D linear thermal expansion

Inputs:

Lref - reference length

Using these functions and other known inputs, the initial subcomponent sizes can be determined. Here is and example of a procedure that could be used to initialize the blade length and rotor and casing radii.
- set a "cold and stationary" temperature and tip clearance for each subcomponent
- set a "cold and stationary" radius/length for 2 of the 3 subcomponents and calculate the "cold and stationary" size of the other subcomponent using the prescribed tip clearance
- compute the unstrained rotor radius by applying "ThermalExpansion1D.m"
- compute the strained rotor radius by applying "RotorStrainExp.m"
- compute the unstrained blade length by applying "ThermalExpansion1D.m"
- compute the strained blade length by applying "BladeStrainExp.m"
- compute the casing radius by applying "ThermalExpansion1D.m"
Note that some adjustments may be required to maintain reasonble tip clearances. The "cold and stationary" tip clearance is a good place to start with the adjustments. If the casing is cooled on the exterior with any significant strength, the casing temperture will not simply be derived from the gaspath temperatures but should consider the temperature of the air and heat transfer coefficient on the outer casing surface. In this case a thermal resistance model can be used to determine the initial steady-state casing temperature.

Further Model Setup

The heat soak and tip clearance models add new states to the model. This includes the temperatures associated with the heat soak model for the compressor as well as the blade and rotor subcomponents used in the tip clearance model. The rate of change in these states must be routed outside the engine models iterative solver loop, integrated, and routed back to the block for the next time-step. The compressor casing temperature must also be computed outside of the block and fed back to it. As mentioned prior, the recommended approach for this is to use a T-MATS 1-D thermal conduction block.

The iDesign tool should still work with this block. However, it should be noted that if iDesign is used, the heat soak and tip clearance effects will not be applied and they will have no effect on the map scaling. One exception is that if a non-zero qext is input, then the it will impact the cycle and map scaling. It is recommended that iDesign be done at a operating point at which thermal equilibrium and nominal tip clearance are achieved.

The heat soak and tip clearance effects can be turned off by setting the block parameters HSopt_M (for heat soak) and TCopt_M (for tip clearance) to zero. To enable them the values should be set to 1.


Instructions

To use this block:

  • Connect the input gas path flow, Rline, and Nmech values to the corresponding places on the block. Do the same for additional inputs.
  • Connect the outputs to the next block(s) in your simulation. Route state derivatives out of the iterative solver later, integrate them, and bring them back at inputs for the next time-step.
  • Double click the block and...
    1. Select which options you will use under each tab:
      • Under the C-Map tab:
        • At the bottom of the page next to "Plot Map" button, check the "Include surge line" box to plot the surge line as defined in the Surge Margin tab. The surge line will not be plotted otherwise.
        • In the bottom-right corner of the page, select which (if any) scalars you will use for the plot.
          Options include:
          1. None: Plots the maps as defined.
          2. User Defined: Plots the maps with Wc, PR, and Eff scaled using the scalars defined in the C-Map tab.
          3. iDesign: Plots the maps with Wc, PR, and Eff scaled using the scalars calculated with iDesign, as defined in the iDesign tab.
      • Under the Surge Margin tab:
        • Check the box to use the map default surge line.
        • Uncheck the box to specify your own values to determine the surge line.
      • Under the iDesign tab:
        • Select the value of iDesign_M.
          Options include:
          • 0: iDes will be enabled and the compressor map scalars will be based on design variables specified by the user in the iDesign tab.
          • 1: Compressor map scalars will be determined from a specified file (FVar_M) that is uploaded by the user and specified in the iDesign tab.
          • 2: Compressor map scalars will be determined by the scalars specified in the C-Map tab; no values from the iDesign tab will be used.
    2. Input the corresponding values for the parameters you have chosen. This includes the new tabs: "Heat Soak", "Tip Clearance", and "Performance Impacts" to use.
